## Selected Console Layout

| Range | Owner | Notes |
|---|---|---|
| `E800h-EA4Eh` | Direct LunchCrema V9958 console | CP/M console semantics, ANSI/VT100-light parser, CP850 atlas, printable-run buffer, and sprite-cursor state. |

The IOC transport uses SIO1/B as its Command lane and SIO1/A as its Bulk lane. Both run the common A5/5A packet with persistent External Sync and Auto Enables off.
`IOCALL` mailbox code is at `E77Bh-E7FDh` in core BIOS; packet helpers occupy `F000h-F414h` and `EC40h-EE7Ch`.
The SD-card BIOS backend follows at `F440h-F513h`; the generated overlap check validates these adjacent ranges.
The SD selection probe is one contiguous block at `F8D0h-F917h`; it was previously four fragments wedged into unrelated gaps.
USB keyboard mailbox and queue state occupies `F5C0h-F5F8h` in the fixed gap after the SD backend.

## Validation Report

Status: PASS. No fatal layout errors were found.

Validated expectations:

- BIOS core must stay inside CBIOS_CORE_BASE-CBIOS_CORE_END.
- Core BIOS component ranges must not overlap.
- Each declared driver must stay inside its declared fixed slot range.
- Selected console driver must stay inside its declared driver-slot range.
- Shared VDrip transport, when selected, must stay inside slot 5.
- Drive-A storage backend must stay inside slot 5.
- SIO core and its exact IM2 vector entry must stay inside core BIOS.
- Scratch buffers and the storage allocation vector must not overlap resident code.
- Runtime state must not overlap scratch, stack, or the SIO-owned IM2 table.
- Stack guard must remain above runtime state.
- Protected/common TPA C000h-C3FFh is application-owned and must not be used by BIOS.

Additional notes:

- CP/M drive A uses the `rom` build-time backend; drive B remains the SD-card backend.
- The direct console links no Virtual Drip transport, readiness, proxy-keyboard, or packet-output code.
- The protected TPA marker is `C000h-C3FFh`; for this build, the application-usable protected TPA subrange is `C000h-C3FFh` because `CBASE` starts at `CC00h`.
- WBOOT restores the CCP range `CC00h-D405h` from ROM page 0 using `ROM_VISIBLE_BANK0` (`00h`) before returning to `CCP_CLEARBUF_ENTRY`.
- `CBIOS_BASE` is `E200h`; CBIOS layout constants are derived from this base.
- `CBIOS_CODE_LIMIT` is `FA80h`; no resident code may cross into scratch/staging.
- SIO core code starts at `E510h` inside core BIOS; the selected console driver starts at `E800h`, and the drive A: storage backend starts at `F6B0h`.
- `IOCALL` code is at `E77Bh` in core BIOS; SIO1/B Command and SIO1/A Bulk use the same persistent-External-Sync common packet.
- `VIDEO_SEND` code is at `E750h` in core BIOS; raw VDP/display writes may desynchronize the V9958 logical-cell state.
- `WBOOT` resident code starts at `E2E8h`, inside protected high BIOS memory.
- `ZBIOS_EXT_BASE` is at `E233h` and exposes `MOVE`, `XMOVE`, `SELMEM`, `SETBNK`, `IOCALL`, `VIDEO_SEND`, `IOCBULK` and `IOCBULKW`.
- The burnable image is `build/zephyr80.bin`.
