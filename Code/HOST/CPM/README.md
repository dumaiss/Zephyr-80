# Zephyr-80 CP/M Port

Initial scaffold for a future CP/M port on the Zephyr-80 homebrew Z80 machine.

This is not yet a working CP/M port. The first goal is to define a CP/M
2.2-style CBIOS jump table and small stub routines that can later be called by
the monitor and eventually by CP/M.

The ROM image now includes an initial Zephyr-80 boot-copy skeleton. The reset
vector at `0000h` jumps into high ROM code in the `E000h-FFFFh` safe/common
area. That code copies ROM contents into SRAM banks using the memory decoder's
shadow-safe mode, disables ROM, initializes a high common stack, and enters a
temporary RAM-resident CBIOS BOOT path.

The current BOOT path initializes SIO channel B, installs minimal CP/M page-zero
vectors, prints a small skeleton banner, and stops in a simple `CBIOS>` echo
loop. This is still only a CBIOS scaffold; it does not boot CCP/BDOS or perform
disk I/O.

The console routines use Zephyr-80 SIO channel B directly for simple polling
I/O. `CONST`, `CONIN`, `CONOUT`, `LIST`, `PUNCH`, `READER`, and `LISTST` are
implemented with CP/M-style register conventions. Disk routines are placeholders
until Zephyr-80 storage exists.

Generated HEX, binary, listing, and object files are build artifacts. They
should be generated by the build system, not hand-authored.

## Build

```sh
make
```

Outputs are written under `build/`:

- `build/cbios.ihx`: Intel HEX output from ASxxxx link
- `build/cbios.raw.bin`: full-size ROM image before the CPU-board data-bit fix
- `build/cbios.bin`: final ROM image after the bit-swap fix
- `build/cbios.lst`: assembler listing, when supported by the assembler

This project mirrors the monitor's ASxxxx toolchain and uses the same
`swapbits.py` data-bit fix step for the final ROM image. Override `SDASZ80`,
`SDLDZ80`, `MAKEBIN`, `PYTHON`, or `SWAPBITS` if your local tool names or paths
differ.

To verify the boot-copy layout after building, inspect `build/cbios.lst` and
confirm:

- `reset_vector` is assembled at `0000h`
- `cbios_jump_table` is assembled at `E000h`
- `cpm_rom_entry_high`, `shadow_copy_rom_to_ram`, and
  `cbios_boot_after_rom_copy` are assembled in `E000h-FFFFh`
- `boot`, `wboot`, `sio_init`, `const`, `conin`, and `conout` are assembled in
  `E000h-FFFFh`

## Current Boot Flow

1. Reset at `0000h` jumps to `cpm_rom_entry_high`.
2. The high-safe boot-copy routine copies ROM pages into RAM and disables ROM.
3. `cbios_boot_after_rom_copy` initializes `SP` in high common RAM.
4. `BOOT` initializes SIO channel B, sets the default DMA address to `0080h`,
   installs `JP WBOOT` at `0000h` and `JP BDOS_STUB` at `0005h`, prints the
   banner, and enters the placeholder echo loop.

Remaining major work: integrate BDOS/CCP, implement storage, define disk
parameter tables, implement real warm boot behavior, and finalize ROM packaging.
